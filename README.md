# 退款申请处理流程

这是一个面向线上课程 / 会员服务产品的退款申请处理 Demo，目标是帮助客服新人按照统一流程判断退款申请，减少处理结果不一致、重复询问和错误升级的问题。

## 项目内容

项目包含两部分：

1. 业务分析材料：记录从初始 Prompt、AI 初步理解、人工质疑、规则修正，到流程拆解和验收的完整过程。
2. 退款申请处理助手：根据申请信息生成当前状态、命中规则、下一步操作、风险标记和管理者确认提示。

## 在线 Demo

[打开退款申请处理助手](00_退款处理Demo/退款申请处理助手.html)

Demo 是一个无需登录的单文件页面，不连接真实支付系统或数据库，退款执行和人工审核均为流程模拟。

## 当前业务规则

- 购买 7 个自然日内且未使用核心服务，系统可自动通过并执行退款。
- 超过 7 个自然日，或用户已使用核心服务，需要人工审核。
- 单笔退款金额超过 500 元，需要管理者确认。
- 近 7 天内退款达到 2 次，需要标记风险；当前 Demo 同时转人工审核。
- 信息不完整时进入“补充材料中”，不能直接拒绝。
- 人工审核可以产生“通过”或“拒绝”；选择拒绝时必须填写拒绝原因。
- 申请最终状态包括：通过、拒绝、补充材料中、人工审核中。

## 处理流程

1. 确认用户、订单和退款时间信息。
2. 检查申请信息是否完整。
3. 检查近 7 天退款次数和异常情况。
4. 判断是否需要人工审核。
5. 判断是否需要管理者确认。
6. 输出用户状态并执行对应的后续动作。

## Demo 输入

- 用户 ID、订单号
- 购买时间、退款申请时间
- 退款金额
- 是否使用核心服务
- 近 7 天退款次数
- 信息是否完整、缺失材料
- 可选异常情况：订单查不到、购买时间查询失败、核心服务使用记录异常

进入人工审核后，页面会显示人工审核结论入口。选择“拒绝”时，必须填写拒绝原因。
